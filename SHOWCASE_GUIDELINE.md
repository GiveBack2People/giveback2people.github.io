# GiveBack2People Project Showcase: Build Guideline for Antigravity

A minimal GitHub Pages site that lists the public repositories of the **GiveBack2People** organization as clean project cards, in the spirit of GitHub's own profile-page layout (identity rail on the left, project grid on the right), styled with the **Lift** brand kit.

**Hosting:** GitHub Pages, in the `giveback2people.github.io` repository.
**Excluded from the list:** `giveback2people.github.io` and `.github`.

---

## 0. Read First

**Inputs you must read before building**
1. `START-HERE.md` and `guidelines/usage-guide.md` from the logo kit. *I have not seen `usage-guide.md`.* Its rules on clear space, minimum sizes, and typography **override anything in this document** that conflicts with them.
2. The reference layout (GitHub profile-page style): left identity column, "projects" card grid with repo name, description, language, stars and forks.
3. `brand-preview.png` for the colors and the overall feel.

**Inspect the existing `giveback2people.github.io` repo first.** I haven't seen what's in it. Don't overwrite existing content without checking it with the owners.

**Decisions made for you** (change only with the owners' agreement)

| Decision | Choice | Why |
|---|---|---|
| Rendering | **Pre-built static HTML**, generated by one Node script in a GitHub Action | No visitor-side API calls, instant load, works without JavaScript, no rate-limit failures |
| Data source | GitHub REST API, `GITHUB_TOKEN` in CI | Public repo data only; authenticated limit is far above what we need |
| Refresh | Every 6 hours, on every push, and manually | Fresh enough; cheap |
| Frameworks | **None.** Plain HTML, one CSS file, one tiny inline script (theme toggle) | The page is small; a framework adds cost and no value |
| Theme | Light and dark, follows the system, manual toggle | Brand kit ships both |

**The simpler alternative (not recommended):** fetch from the API in the visitor's browser. Unauthenticated requests are limited to 60 per hour *per IP address*, so shared networks (offices, schools, VPNs) would see a broken page, and visitors would watch cards pop in after load.

## 1. Scope

**In:** one page (`/`), identity rail, project grid, theme toggle, footer, favicons from the brand kit, automatic data refresh.
**Out (for now):** search, pagination, per-project pages, analytics, a blog, contact forms, cookie banners. If the org grows past roughly 20 projects, add a filter (section 5.5).

## 2. Brand Rules

Use the **exact** assets from the logo kit. Do not redraw, recolor, stretch, or add effects to the logo.

| Need | Use |
|---|---|
| Header/rail logo on light | `svg/horizontal-color-light.svg` |
| Header/rail logo on dark | `svg/horizontal-color-dark.svg` |
| Favicon, Apple touch icon, manifest | the `web/` folder and its installation snippet, copied as provided |
| GitHub avatar | `png/avatar-dark.png` (done by owners in org settings, not part of this build) |

Because the theme can be toggled manually, don't swap logos with `<picture media="(prefers-color-scheme)">`. Render **both** `<img>` elements and show one via CSS (`[data-theme="light"] .logo-dark { display: none }` and the reverse). Give the visible logo `alt="GiveBack2People"`, and hide the other from assistive tech.

### 2.1 Palette (from the brand kit)

| Brand color | Hex | Role on this site |
|---|---|---|
| Indigo | `#6366F1` | Fills, focus rings, hover borders, decorative accents |
| Cyan | `#06B6D4` | **One small highlight only** (the "Featured" dot). Never body text on light |
| Obsidian | `#0F172A` | Dark-theme page background; light-theme text |
| White | `#FFFFFF` | Light-theme cards; text on dark fills |

**Rule:** indigo carries structure, cyan appears at most once per card, and nothing else is colored. No gradients, no glows, no colored shadows.

### 2.2 Theme tokens

Neutrals are slate tints that sit next to Obsidian. All contrast ratios below were computed.

| `--border` | `#E2E8F0` | `#1E293B` |
| `--control-border` (inputs, toggle) | `#64748B` | `#64748B` |
| `--text` | `#0F172A` | `#E2E8F0` |
| `--text-muted` | `#475569` | `#94A3B8` |
| `--link` | `#4F46E5` | `#818CF8` |
| `--accent` (focus, hover border) | `#6366F1` | `#6366F1` |
| `--highlight` (Featured dot) | `#06B6D4` | `#06B6D4` |

### 2.3 Contrast, checked

| Pair | Ratio | Verdict |
|---|---|---|
| Light: `--text` on white | 17.85 | Pass |
| Light: `--text-muted` on white | 7.58 | Pass |
| Light: `--link` `#4F46E5` on white | 6.29 | Pass |
| Dark: `--text` on `#0F172A` | 14.48 | Pass |
| Dark: `--text-muted` on `#0F172A` | 6.96 | Pass |
| Dark: `--link` `#818CF8` on `#0F172A` | 5.98 | Pass |
| Focus ring `#6366F1` on white / on Obsidian | 4.47 / 4.00 | Pass (needs 3:1) |
| Control border `#64748B` on white / on Obsidian | 4.76 / 3.77 | Pass (needs 3:1) |

**Two traps from the brand palette itself:**
- Brand Indigo `#6366F1` on white is **4.47:1**, just under the 4.5:1 needed for text. **Never use it as link or body text on light.** Use `#4F46E5` for text and links, and keep `#6366F1` for fills, borders, and focus.
- Brand Cyan on white is **2.43:1**. It is a decorative dot, never text, on a light background.

If a filled button is ever needed: white text on `#4F46E5` (6.29:1), not on `#6366F1`.

### 2.4 Typography

Default to **Geist** (variable, self-hosted, Latin subset, `font-display: swap`) so the site matches the Design Resources spec, with the system sans stack as fallback. **If `usage-guide.md` names a brand typeface, use that instead.** (The `brand-preview` sheet uses Segoe UI only as a presentation font; don't treat that as the brand font.)

| Role | Size / line | Weight |
|---|---|---|
| Page title (H1 "Projects") | 28 / 36 | 600 |
| Card title | 16 / 24 | 600 |
| Body, descriptions, rail text | 14 / 22 | 400 |
| Meta (stars, language, date) | 12 / 16 | 500, `tabular-nums` |

Tracking `-0.01em` on the H1 only. Sentence case everywhere.

## 4. Identity Rail

Top to bottom:
1. **Logo**: the horizontal lockup, about 200px wide, links to `/`.
2. **Tagline**: "Open knowledge. Shared forward." (14/22, `--text`, 600).

## 5. Main Column

### 5.1 Header

H1 "Projects", then one muted line: "Open-source work from the GiveBack2People community." followed by the **computed** count ("7 projects"). Never hardcode the count.

### 5.2 Project card

```
┌──────────────────────────────────────┐
│ ▯  repo-name                   ● Featured │   ← repo glyph, name (link), pinned marker
│                                      │
│  Description, up to three lines,     │
│  then it truncates with an ellipsis. │
│                                      │
│  ● JavaScript   ★ 1.2k   ⑂ 48        │   ← meta row
│  design  resources  open-source      │   ← up to 3 topics (only if present)
└──────────────────────────────────────┘
```

| Element | Spec |
|---|---|
| Container | `--surface`, 1px `--border`, radius 12, padding 20, min-height 140, flex column, 12px gap |
| Repo glyph | 16px outline repo/book icon, `--text-muted` |
| Name | 16/24, 600, `--link`. A stretched link covers the whole card (`::after` on the title link, `inset: 0`). Opens the repo in the same tab |
| Featured marker | 6px `--highlight` dot + "Featured" (12px, `--text-muted`), top-right. Only for pinned repos |
| Description | 14/22, `--text-muted`, clamp 3 lines. If empty: show nothing (no placeholder text, no empty gap) |
| Language | Small dot in `--text-muted` + the language name. **One neutral dot color for every language**: GitHub's language-color rainbow would fight the brand. The name carries the meaning, not the dot |
| Stars, forks | Icon + number, `1.2k` format. **Hide when 0** |
| Topics | Up to 3 neutral pills (12px, 1px `--border`, `--text-muted`), only if the repo has topics |
| Live site | If the repo's `homepage` is set and valid: a secondary `Website ↗` link (above the stretched link, `position: relative; z-index: 1`) in the meta row |

**States**
- Rest: as above.
- Hover: border becomes `--accent` at 50% opacity; `translateY(-1px)`; 150ms. No shadow.
- Focus-visible: 2px `--accent` ring, 2px offset.
- Active: no lift.

### 5.3 Sorting and visibility rules (all driven by `config.json`)

1. Remove excluded names: `giveback2people.github.io`, `.github` (compare case-insensitively).
2. Remove private repos (the API returns only public ones without extra permissions; double-check the `private` flag anyway).
3. Remove forks and archived repos by default (`hideForks`, `hideArchived`).
4. Remove any repo carrying the topic `hide-from-showcase`. This gives maintainers an opt-out without touching code.
5. Order: **pinned repos first** (in the order listed in `pin`, e.g. `designresources`), then by most recently pushed.

### 5.4 Empty and error states

- **No projects after filtering:** show "No public projects yet." with a link to the GitHub organization. (The build should normally refuse to deploy this; see 6.4.)
- **JavaScript disabled:** everything works; only the theme toggle is inert (theme follows the system).

### 5.5 Optional, off by default

- **Topics section**: replaces the reference's "My Interests". A row of topic chips aggregated from the shown repos (up to 12), linking to that topic's search in the org. Enable with `showTopics` only when there are at least 3 distinct topics.
- **Filter box**: appears only when there are more than 12 projects. Plain text filter by name/description, `/` to focus. Build it only when needed.

### 5.6 Footer

One line, 12px muted: "Updated 18 Nov 2026" (build date in UTC, rendered at build time) · "Source on GitHub" (links to the site's own repo). The date also tells maintainers when the scheduled build has silently stopped (see 6.5).

## 6. Data Pipeline

### 6.1 Repository layout (in `giveback2people.github.io`)

```
/
├─ config.json
├─ scripts/build.mjs            # fetch, filter, render, write dist/
├─ src/
│   ├─ template.html            # page shell with placeholders
│   ├─ styles.css
│   └─ theme.js                 # < 1 KB, inlined into the page
├─ public/                      # copied as-is: web/ favicons, svg logos, fonts
├─ data/sample.json             # fixture for local design work
├─ dist/                        # generated, gitignored
└─ .github/workflows/pages.yml
```

### 6.2 `config.json`

```json
{
  "org": "GiveBack2People",
  "exclude": ["giveback2people.github.io", ".github"],
  "hideTopic": "hide-from-showcase",
  "hideForks": true,
  "hideArchived": true,
  "pin": ["designresources"],
  "sort": "pushed",
  "showTopics": false,
  "minRepos": 1,
  "links": [
    { "label": "GitHub", "url": "https://github.com/GiveBack2People" }
  ]
}
```

All behavior changes happen here, not in code.

### 6.3 `scripts/build.mjs` behavior

1. Request `GET https://api.github.com/orgs/<org>/repos?type=public&per_page=100&sort=pushed`, following pagination until no more pages. Use Node's built-in `fetch`; send `Authorization: Bearer $GITHUB_TOKEN` when the variable exists (it will in CI) and an `Accept: application/vnd.github+json` header. Without a token the script still works locally within the 60-requests-per-hour anonymous limit.
2. Keep only the fields used: `name`, `description`, `html_url`, `homepage`, `language`, `stargazers_count`, `forks_count`, `topics`, `archived`, `fork`, `private`, `pushed_at`. Confirm `topics` is present in the list response; if not, fetch topics per repo.
3. Apply the rules in 5.3.
4. Render the cards into `src/template.html` and write everything to `dist/`, copying `public/`.
5. Accept `--offline` to read `data/sample.json` instead of the network, so design work needs no API access.

**Security (mandatory):**
- **Escape every string** from the API (names, descriptions, topics) before inserting it into HTML. Repo descriptions are user-controlled content.
- Only render `homepage` if it parses as an `http:` or `https:` URL. Drop anything else.
- All external links get `rel="noopener noreferrer"`.

### 6.4 Failure behavior

- Any non-200 response, network error, or a result with fewer than `minRepos` projects: **exit non-zero.** The workflow then fails and GitHub keeps serving the last good deployment. Never deploy an empty or partial page.
- Log the rate-limit headers when a request fails.

### 6.5 Workflow (`.github/workflows/pages.yml`)

Deploy through GitHub Actions rather than committing generated files back to the repo.

```yaml
name: pages
on:
  push: { branches: [main] }
  schedule: [{ cron: "17 */6 * * *" }]   # every 6 hours (UTC)
  workflow_dispatch:

permissions: { contents: read, pages: write, id-token: write }
concurrency: { group: pages, cancel-in-progress: true }

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: node scripts/build.mjs
        env: { GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }} }
      - uses: actions/upload-pages-artifact@v3
        with: { path: dist }
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment: { name: github-pages, url: "${{ steps.d.outputs.page_url }}" }
    steps:
      - id: d
        uses: actions/deploy-pages@v4
```

Use the current major version of each action and the current Node LTS when you build this; the versions above are a sketch.

**One-time repo setting:** Settings, then Pages, then set the source to **GitHub Actions**.

**Facts that shaped this design** (from GitHub's docs):
- Unauthenticated REST requests are limited to 60 per hour per IP address; `GITHUB_TOKEN` in a workflow gets 1,000 per hour per repository. The build needs one or two requests.
- **Scheduled workflows in public repositories are automatically disabled after 60 days with no repository activity.** This site's repo may easily go quiet that long. Mitigations: (a) the footer shows the build date, so staleness is visible; (b) the owners keep a monthly reminder to open the Actions tab, or make any small commit to reactivate it; (c) any push also triggers a fresh build.

## 7. Accessibility

- Landmarks: `<header>` (rail or top block), `<main>`, `<footer>`. One `<h1>` ("Projects"). Add a visible-on-focus skip link to `main`.
- Cards are a list (`<ul><li>`). The stretched-link pattern means the **title link is the only link for the card**; the optional Website link is a separate, real link above it. Never nest links.
- Visible focus on every interactive element (2px `--accent` ring).
- Color is never the only signal (language has its name; Featured has text).
- Theme toggle: a `<button>` with a label that states the action; the page declares `color-scheme: light dark`.
- Respect `prefers-reduced-motion` (the card lift only runs when motion is allowed).
- Set `<html lang="en">`.
- Target: Lighthouse Accessibility 100 and one keyboard-only pass.

## 8. Performance and Meta

- Whole page under 100 KB excluding the logo SVG and the font. CSS inlined or one file; JS only the inline theme script.
- Prevent the theme flash: a tiny inline script in `<head>` sets `data-theme` from `localStorage` or the system preference before first paint.
- No layout shift: logo with explicit width and height; font with `font-display: swap` and a metric-compatible fallback.
- `<title>`: `Projects · GiveBack2People`. Meta description: the brand blurb (section 4). Add Open Graph and Twitter tags with an image generated from the kit once available (1200x630).
- Favicons, Apple touch icon, and manifest: install exactly as the kit's snippet in `web/` says.

## 9. Definition of Done

**Content and data**
- [ ] `giveback2people.github.io` and `.github` never appear, in any state
- [ ] Forks, archived repos, and repos tagged `hide-from-showcase` are hidden by default
- [ ] `designresources` (when pinned) appears first, with the Featured marker
- [ ] Project count is computed, never typed in
- [ ] Repos with no description, no language, zero stars, long names, and 10+ topics all render cleanly
- [ ] A description containing `<script>` or HTML shows as plain text
- [ ] Build fails (and the old site stays up) when the API errors or returns too few repos

**Brand and visual**
- [ ] Logo files are the originals from the kit, unmodified, with the right one per theme
- [ ] Only the listed tokens are used; no raw hex in components
- [ ] Indigo `#6366F1` is never used for text on light; cyan appears at most once per card
- [ ] Light and dark verified at 320, 768, and 1440px

**Quality**
- [ ] Works with JavaScript disabled
- [ ] Keyboard and screen-reader pass; Lighthouse Accessibility 100
- [ ] Scheduled run and manual run both succeed; Pages source is set to GitHub Actions
- [ ] Footer date updates after a scheduled run

## 10. Decisions for the Owners

1. **Pinned and featured repos:** is `designresources` the only one to pin?
2. **Forks and archived repos:** hidden by default. Change `hideForks` / `hideArchived` if you want them shown.
3. **Stars and forks on cards:** shown only when above zero. If the org is young, you may prefer to hide them entirely (a small config flag).
4. **Typography:** confirm the brand typeface from `usage-guide.md`; Geist is the placeholder default.
5. **Consistency with Design Resources:** that spec currently uses `#0A0A0B` as its dark background and a different accent. The brand kit says Obsidian `#0F172A` and Indigo `#6366F1`. Recommend aligning the Design Resources tokens to the brand palette so the two sites read as one organization.
